# Chemotion IR inventory

Generated by `scripts/inventory.py` from the Chemotion IR collection
(RADAR4Chem, DOI 10.22000/OGoEQGlsZGElrgst, CC BY-SA 4.0). One row per
JCAMP-DX file in `data/processed/inventory.csv`; this file summarises it.

Dataset directory: `data/raw/10.22000-OGoEQGlsZGElrgst/data/dataset`

**Unit of analysis.** Chemotion exports every measurement more than once:
a raw attachment and a peak-picked one, and both carry the full XYDATA
block, so the raw file count is close to twice the number of measurements.
Every count below other than sections 1 and 2 is taken over one row per
analysis id, selected by the `is_primary_export` column of the CSV.

## 9. Notes

- The spectrum files carry no extension and are named by the UUID that
  closes the `identifier` field of each attachment in `meta_data.json`.
- Chemotion writes a descending point counter in the X column of the
  XYDATA block instead of the wavenumber, so the X axis is reconstructed
  from `##FIRSTX`, `##LASTX` and `##NPOINTS`. The `jcamp` library does
  this correctly but emits an X-check warning per line, suppressed here.
- Most analyses appear twice, as a `.dx` and a `.jdx` attachment, and
  both files carry the same XYDATA block. The `is_primary_export` column
  marks one row per analysis id, preferring `.dx` over `.jdx` over
  `.peak.jdx`, and preferring rows that pass the quality filters. No
  analysis in this release disagrees between its exports on point count.
- Files whose only data block is a peak table raise `flag_no_xy_data`.
  They are kept in the inventory because they record the bands the
  depositors themselves picked, which is a separate object of study.
- `reported_ir_text` holds the IR band list written by the depositor in
  the publication, flattened from the Quill delta in the `content` field.
